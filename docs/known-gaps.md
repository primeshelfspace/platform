# Known gaps

Open items that are decisions or dependencies outside the code — not bugs.
Last checked against the code: October 2026.

| Item                            | Status                                                                                                                                                                                                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Numbers Gateway (DEP-01)**    | The API contract could not be read, so `NumbersGatewayAdapter` is a typed placeholder listing the questions it needs answered. Use `PAYMENT_GATEWAY_DRIVER=fake` or `stripe`.                                                                                       |
| **Card fee base (Q-01)**        | The fee is calculated on the post-tax total (TDD-001 §9.2). Card surcharging is regulated in some US states. Both need a client answer before the fee ships.                                                                                                        |
| **Unit price precision**        | TDD-001 §9.3 writes a unit price with three decimals, which `unit_price_minor` cannot hold; the fixture carries the fraction on the quantity instead (same result). If fractional unit prices are a real requirement, the schema needs a four-decimal price column. |
| **Two-factor sign-in**          | `loginSchema` accepts a `totp` field and `user.totp_secret` exists, but nothing reads either yet.                                                                                                                                                                   |
| **Billing provider**            | Subscriptions exist and gate every product, but no payment provider is connected: an owner switches products on and off by hand in Accounts → Billing. Which provider (and plans/prices) is a business decision.                                                    |
| **Adding brands from Accounts** | Accounts lists brands; adding one still happens in Sugrpay, because creating a brand also sets up its invoice numbering.                                                                                                                                            |
| **HQ**                          | Subscriptions, HQ roles and locations are ready; the HQ module and web app are not built yet — see [architecture/adding-a-product.md](architecture/adding-a-product.md).                                                                                            |
| **Demo company onboarding**     | The seed does not mark the demo company as set up, so the first time the owner opens Sugrpay it asks for the brand structure (pick Multi-brand).                                                                                                                    |
| **Security hardening**          | Three items from the [API test report](api/test-report-2026-10-22.md#findings): owner/admin requests for another company's brand are stopped only by row-level security (no data exposed, but should be 403); CORS accepts every origin; `X-Powered-By` is sent.    |
