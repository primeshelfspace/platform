# Security

How Sugrpay protects accounts, companies' data and money; what the security
audit of October 2026 found and how each finding was fixed; and the tests that
hold every rule in place. The web app's side is in
[sugrpay-frontend/docs/security.md](https://github.com/primeshelfspace/sugrpay-frontend/blob/main/docs/security.md).

## 1. The rules

| Area                | Rule                                                                                                                                                                                                                                                                              | Where                                                                                                                                     | Tested in                                                                                      |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Sessions            | 256-bit random tokens; only their SHA-256 is stored. 12-hour life. Suspended users are refused on every request.                                                                                                                                                                  | `auth/application/session.service.ts`                                                                                                     | `authorisation-guard.test.ts`, e2e 16, 19, 21                                                  |
| Sign-in             | One generic error for every failure; a decoy hash keeps timing equal; lock after 5 failures in 15 minutes.                                                                                                                                                                        | `auth/application/auth.service.ts`                                                                                                        | `auth.service.test.ts`, e2e 3                                                                  |
| Emailed links       | Single-use, 24 hours, a new one cancels the old. Using one signs out every other session. **A suspended account cannot use one.**                                                                                                                                                 | `password-reset.service.ts`, `auth.service.ts`                                                                                            | `signup.test.ts`, e2e 16, 17                                                                   |
| Changing a password | **Needs the current password** (except the first, forced one) and **signs out every other session**.                                                                                                                                                                              | `AuthService.setPassword`                                                                                                                 | `auth.service.test.ts`, e2e 18                                                                 |
| Sign-up             | An address in use gets 409. A waiting sign-up is re-sent its link (**rate-limited**); **another company's pending invitation never captures a sign-up**.                                                                                                                          | `AuthService.register`                                                                                                                    | `signup.test.ts`, e2e 1, 2                                                                     |
| Who may do what     | Every route declares a permission or `@Public`; a route without one is refused. The role matrix is in `packages/kernel/src/domain/roles.ts`.                                                                                                                                      | `packages/server/src/auth/authorisation.ts`                                                                                               | `authorisation-coverage.test.ts`, `authorisation-guard.test.ts`, e2e 15                        |
| Company isolation   | 1) the guard: a brand-scoped role reaches only its brands, and **an owner or admin only their own company's brands**; 2) every query filters by company; 3) PostgreSQL row-level security.                                                                                        | `authorisation.ts` + `brandInCompany` (platform: `SessionService`; Sugrpay: `RemoteScopeResolver`, from its brand copy), `withScope`, RLS | `authorisation-guard.test.ts`, `rls.test.ts`, e2e 20                                           |
| Brand Admins        | May change a user's role, status, product role or locations **only if every brand that user holds is one they administer**.                                                                                                                                                       | `UsersService.assertManagesAllBrandsOf`                                                                                                   | `users.service.test.ts`                                                                        |
| Money               | A card or ACH payment is for **the remaining balance only** (fee on that balance). **One attempt at a time per invoice** (row lock). Money arriving for a paid invoice is **flagged for refund** on the timeline. A webhook whose **amount or currency differs** settles nothing. | `PaymentsService`                                                                                                                         | `payments.service.test.ts`, e2e 8, 9                                                           |
| Checks              | **The reviewer enters the amount on the check**; only that is recorded. **No check uploads on cancelled or paid invoices; at most 3 waiting** per invoice.                                                                                                                        | `ChecksService.approve`, `PublicInvoicesService.submitCheck`                                                                              | `checks.service.test.ts`, `public-invoices.service.test.ts`, e2e 10, 11                        |
| Payment page        | The link token is the only credential (128-bit). **A customer cannot start a MANUAL payment.**                                                                                                                                                                                    | `public-invoices.controller.ts`                                                                                                           | e2e 12, 23                                                                                     |
| Uploads             | **Checked by their bytes, not the claimed type.** **SVG logos may not contain scripts, event handlers, embedded HTML or outside links.** Files served from the API carry `CSP: sandbox`.                                                                                          | `packages/server/src/common/image-content.ts`, `storage.controller.ts`                                                                    | `image-content.test.ts`, e2e 6, 10                                                             |
| Rate limits         | **Sign-in, sign-up, password reset, payment attempts, PDFs and check uploads are limited** per address and per email / payment link. **Invoice and test emails and invitations have a daily quota per company.** Answers 429.                                                     | `packages/server/src/common/rate-limit.ts`, `@RateLimit` on the routes                                                                    | `rate-limit.test.ts`, e2e 25                                                                   |
| Browsers            | **CORS allows only the web app's own addresses** (`ADMIN/ACCOUNTS/PAYMENT_PUBLIC_URL` + `CORS_EXTRA_ORIGINS`). **Every response has `nosniff`, `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `no-referrer`, HSTS over HTTPS; no `X-Powered-By`.**                            | `packages/server/src/common/http-security.ts`, `app-setup.ts`                                                                             | `http-security.test.ts`, e2e 24                                                                |
| Integrations        | OAuth state is signed (HMAC) and expires in 10 minutes; credentials are encrypted (AES-256-GCM). **Connect, pull and backfill on another company's brand are refused by the guard.** **Zoho records are only ever assigned to the caller's own company's brands.**                | `oauth-state.ts`, `credential-encryption.ts`, `zoho-webhook.service.ts`                                                                   | `oauth-state.test.ts`, `credential-encryption.test.ts`, `zoho-webhook.service.test.ts`, e2e 20 |
| Errors in URLs      | **OAuth callbacks put fixed codes in the redirect, never error text**; the detail goes to the log.                                                                                                                                                                                | `zoho-connect.controller.ts`                                                                                                              | —                                                                                              |
| Between the APIs    | `/internal/...` routes skip the user guard but need the shared `INTERNAL_API_KEY` (compared in constant time); nginx refuses `/internal/` on every public name. Production refuses to start without the key (at least 32 characters).                                             | `packages/server/src/internal/internal-key.guard.ts`, `deploy/nginx/api.conf`                                                             | e2e (every Sugrpay call resolves its session this way)                                         |
| Secrets             | Production refuses fake gateway, console mail and local storage. Secrets live only in the server's `.env` (mode 600).                                                                                                                                                             | `packages/server/src/config/env.ts`                                                                                                       | —                                                                                              |

**Bold** = added or changed in the October 2026 audit.

## 2. The October 2026 audit

Two independent reviews (API and web app) plus the earlier API test. Every
finding, and what happened to it:

| #   | Severity | Finding                                                                                                                                | Fix                                                                                            |
| --- | -------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| C1  | Critical | Any new sign-up (an owner) could connect **another company's** brand to their own Stripe/Square/Zoho, redirecting its payments         | The guard checks that a brand named in the URL belongs to the caller's company, for every role |
| H1  | High     | After a partial payment the card/ACH charge was still the full invoice total                                                           | Charge = balance (+ fee on the balance)                                                        |
| H2  | High     | Two simultaneous attempts could both charge; a late second payment was only logged                                                     | Invoice row lock per attempt; a payment landing on a paid invoice adds `PAYMENT_NEEDS_REFUND`  |
| H3  | High     | A suspended user could re-activate themselves with an invite or reset link                                                             | Setting a password from a link refuses a suspended account                                     |
| H4  | High     | A Brand Admin could promote a user who also works on other brands into Brand Admin of those brands                                     | All of the user's brands must be the Brand Admin's                                             |
| H5  | High     | No rate limiting anywhere except forgot-password                                                                                       | `@RateLimit` on every public route worth abusing; 429                                          |
| H6  | High     | Free sign-up + unlimited sending = a phishing relay                                                                                    | Daily per-company quotas on invoice emails, bulk send, test sends, invitations                 |
| M1  | Medium   | Changing a password needed only a session and kept other sessions                                                                      | Current password required; other sessions revoked                                              |
| M2  | Medium   | Inviting an address first captured that person's later self-sign-up                                                                    | Re-send only to the person's own earlier sign-up; otherwise a new company is created           |
| M3  | Medium   | A cancelled invoice still accepted check uploads                                                                                       | Refused unless the invoice is payable; queue capped at 3                                       |
| M4  | Medium   | Approving a check recorded the customer's claim, not the check                                                                         | Reviewer enters the amount (pre-filled with the claim)                                         |
| M5  | Medium   | Zoho pending records could be assigned to another company's brand on the same organization                                             | Candidates limited to the caller's company                                                     |
| M6  | Medium   | OAuth state is not tied to the browser and can be replayed for 10 minutes                                                              | Open — impact now limited to the caller's own brands by C1's fix (see §3)                      |
| M7  | Medium   | No security headers; SVG logos could carry script; uploads trusted the claimed type                                                    | Headers on every response; SVG sanitising check; byte signatures; sandbox CSP on served files  |
| M8  | Medium   | CORS accepted every origin                                                                                                             | Allowlist                                                                                      |
| L   | Low      | `MANUAL` accepted from the payment page; no length caps on some inputs; error text in callback URLs; webhook amounts not cross-checked | All fixed                                                                                      |

## 3. Still open

| Item                                  | Why it is acceptable for now / what to do                                                                                                                                                                                 |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OAuth state not browser-bound (M6)    | Replaying a state can only connect the caller's own brand. Fix: a `__Host-` nonce cookie in the HMAC and single-use state in Redis.                                                                                       |
| Open Stripe intents not cancelled     | A second tab can still hold a live Stripe intent; if both are paid the second is flagged `PAYMENT_NEEDS_REFUND` for staff. Fix: reuse the open intent, cancel on manual payment or cancel.                                |
| Per-address limits behind the web app | Sign-in/sign-up come through the web app's server, so their per-address limit is a loose global brake; the per-email limit is the real one. Fix: have the web app forward the client address in a signed header.          |
| Admin pages' script CSP               | `/pay` has a full nonce CSP; admin and Accounts have a baseline (no framing, no plugins, forms to self). React escapes output and there is no `dangerouslySetInnerHTML`. Fix: extend the nonce middleware to every route. |
| Two-factor sign-in                    | Schema exists, not implemented (see [known-gaps.md](known-gaps.md)).                                                                                                                                                      |
| Email authentication                  | `sugrpay.com` has no SPF/DKIM yet (DMARC is quarantine), so mail may land in spam — a DNS task.                                                                                                                           |
| Credentials pasted in chat            | Rotate the RDS master, SMTP app password, Stripe and Zoho secrets that were shared during setup.                                                                                                                          |

## 4. Running the security tests

```bash
pnpm db:seed          # local database only — never on production
pnpm test
```

All unit, database and end-to-end tests run together (`pnpm check` runs them
too). The end-to-end suite, `e2e/user-journeys.test.ts` (package
`@platform/e2e`), boots the platform and Sugrpay APIs as production configures
them, sends each call to the API that owns it (`apiServiceFor`), and walks
every user journey listed in
[testing/user-scenarios.md](testing/user-scenarios.md).
